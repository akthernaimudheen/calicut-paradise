# Calicut Paradise — website concept

A mobile-first, premium website concept for **Calicut Paradise**, a Malabar restaurant at
Confident House, 622 Ikkanda Warrior Road, Kokkala, Veliyannur, Thrissur 680021.

The site replaces a Linktree page with a branded site plus an interactive menu that turns a
dish list into a formatted WhatsApp order enquiry.

> **Status: independent concept, pending restaurant approval.**
> Nothing here is deployed against a Calicut Paradise-owned domain, and no restaurant-owned
> property has been modified. Photography slots are labelled placeholders — see
> [docs/asset-manifest.md](docs/asset-manifest.md).

---

## Stack

| Concern    | Choice |
| ---------- | ------ |
| Framework  | Next.js 16 (App Router, Turbopack) |
| Language   | TypeScript (strict) |
| Styling    | Tailwind CSS v4 (CSS-first theme) |
| Motion     | Framer Motion |
| Icons      | Lucide React |
| Fonts      | Playfair Display + Plus Jakarta Sans via `next/font/google` |
| Backend    | None. The cart lives in the browser; every action leads to WhatsApp, tel: or Maps. |

## Run it

```bash
npm install
npm run assets     # (re)generate the placeholder plates + favicon
npm run dev        # http://localhost:3000
```

```bash
npm run typecheck  # tsc --noEmit
npm run lint       # eslint (flat config, eslint-config-next)
npm run test       # node --test tests/ — WhatsApp message builders
npm run build      # production build
npm start          # serve the production build

# optional browser QA — Playwright is intentionally not a dependency
npm i -D playwright && node scripts/qa.mjs
```

Environment (optional, for canonical URLs):

```bash
cp .env.example .env.local
# NEXT_PUBLIC_SITE_URL=https://preview.example.com   → canonical, OG, sitemap, robots
```

## Routes

| Route      | Purpose |
| ---------- | ------- |
| `/`        | Cinematic hero, quick-action strip, introduction, signatures, menu sections, Malabar story, gallery, ambience, review themes, location/parking, reservation enquiry |
| `/menu`    | Searchable 8-section menu, deep links (`/menu?c=biryani`), quantity controls, sticky enquiry summary, mobile cart bar |
| `/reserve` | Standalone table reservation enquiry |
| `/robots.txt`, `/sitemap.xml` | Configurable from `NEXT_PUBLIC_SITE_URL` |
| `/opengraph-image` | 1200×630 social card rendered at request time |

## The WhatsApp enquiry flow

1. A visitor taps **Add** on any dish (`components/cart/quantity-control.tsx`).
2. Quantities persist in `localStorage` through a small external store
   (`lib/cart-store.ts`), so a reload keeps the enquiry.
3. The cart sheet (`components/cart/cart-sheet.tsx`) collects order type — dine-in
   pre-order / takeaway / delivery enquiry — plus name, optional phone and notes.
4. Sending opens `https://wa.me/919562367000?text=…` with a formatted, itemised message.

The UI states plainly that this is an **enquiry**, not a confirmed order: no payment is
taken, no delivery partner is booked, and the total shown is derived from publicly listed
prices and marked indicative.

## Business-data status

Every unverified field is flagged in code (`verify: true` in `lib/site.ts`,
`verified: false` per dish) and listed in
[docs/missing-information.md](docs/missing-information.md). Only the phone number, address
and name are treated as settled.

## Photography

`public/images/` uses fixed slot names, one JPEG per shot, grouped by section. Replacing a
file with a licensed original is the entire migration — no code change. Once all slots hold
real photographs, set `assets.photoPlaceholders: false` in `lib/site.ts` to hide the
"Placeholder" badges.

## Deploy

See [docs/deployment.md](docs/deployment.md). Short version: any Node host that runs
`next build` / `next start`, with `NEXT_PUBLIC_SITE_URL` set to the final origin.
